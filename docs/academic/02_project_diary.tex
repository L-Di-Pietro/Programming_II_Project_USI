\section{Project diary}
\label{sec:diary}

The four-week development cycle was punctuated by eight merged pull requests and a
handful of direct-to-\texttt{main} commits for docs and trivia. The narrative below
follows the actual order of decisions, with commit hashes given so a reviewer can
verify any claim from \texttt{git log}.

\subsection*{Week~1 \textemdash{} Foundation (2026-04-25 to 2026-04-29)}

The first commit (\texttt{4ff85c1}) bootstrapped an empty repository. Four days
later, \texttt{ecdf3bb} (``Initial project scaffold for QuantEdge'') landed the
full directory layout we would carry through the project: a \texttt{backend/}
package with \texttt{agents/}, \texttt{api/}, \texttt{analytics/},
\texttt{backtest/}, \texttt{data/}, \texttt{database/}, \texttt{llm/},
\texttt{strategies/} subpackages; a \texttt{frontend/} folder primed for Vite; a
\texttt{tests/} folder; and \texttt{requirements.txt} pinning the backend stack.
The agent boundaries were committed to at this stage rather than discovered later
\textemdash{} we used the breakdown in the rubric (data, strategy, backtest,
analytics, orchestrator, explanation) as the starting point and held to it.

\subsection*{Week~2 \textemdash{} First domain feature + first LLM call (2026-05-08)}

Two commits on the same day represent the project's two first proofs of life. PR~\#1
(\texttt{376d30e}, ``feat: add TSLA as new equity asset'') validated the end-to-end
data path: register an asset in the seed list, run \texttt{load\_initial\_data.py},
see daily bars appear in the database. \texttt{8997d20} (``feat: add LLM generated
report'') validated the LLM seam: we wanted to make sure the \texttt{LLMProvider}
abstraction could carry a real response before we built the rest of the analytics
layer around it.

We deliberately wrote the LLM feature \emph{first} as a worst-case probe. If it
worked, every other deterministic feature would be easier; if it failed, we had time
to redesign. It worked, and the rest of the project never had to compromise its
determinism for the sake of the AI report.

\subsection*{Week~3 \textemdash{} Frontend MVP, hourly bars, charts (2026-05-12 to 2026-05-16)}

Frontend Version~1 (\texttt{1f2f5c7}) landed on 2026-05-12. The same day, PR~\#2
(\texttt{1f13139}, ``Add native calendars and hourly bar support'') reshaped the
data layer: the OHLCV composite primary key became \texttt{(asset\_id, ts,
timeframe)}, so daily and hourly bars could coexist for the same asset, and the
\texttt{OHLCVCleaner} learned to reindex onto NYSE for equities, a bespoke
24$\times$5 window for FX, and 24$\times$7 for crypto. This was the project's most
intricate single change: a missed edge case in any of the three calendars would have
silently misstated the annualisation factor for every Sharpe ratio we report.

The chart suite then went through a flurry of small fixes (\texttt{3e22d4c},
\texttt{162ceba}, \texttt{ab1e2de}) that brought the strategy-category badges,
chart-tooltip alignment, and sidebar navigation up to standard. \texttt{a3b6635}
(``Chunk upserts, add LLM retries, and fix time indexes'') addressed the SQLite
parameter-count ceiling we hit when bulk-loading multi-year hourly history.

Late in the week, the PDF-export feature shipped (\texttt{0a7edb1}). The choice to
render the report client-side via \texttt{jsPDF} rather than server-side via a
headless browser kept the backend dependency footprint small and avoided the need
for the OS-level Chromium libraries that other PDF approaches require.

\subsection*{Launcher hardening and production Docker setup (2026-05-28)}

The commits merged as PR~\#16 (\texttt{ed31a92}, \texttt{b8c9332}, \texttt{533dedb})

\subsection*{Frontend polish and backtest isolation (2026-05-29)}

The day's work divided into two tracks that shipped in the same afternoon.

The first was a front-end polish sprint. The most visible addition was an interactive
onboarding tour (\texttt{b3acd7d}): \texttt{OnboardingTour} is mounted once at the app
root and spotlights one UI element per step. \textit{Active} steps ask the user to
click the highlighted control before the tour advances, so first-time users learn by
doing rather than by reading a static help page. The tour is replayable via a ``Replay
tour'' footer link at any time. A companion commit (\texttt{a7ffe1c}, PR~\#18) replaced
the per-page ad-hoc spinners across \texttt{NewBacktest}, \texttt{RunResults}, and
\texttt{Strategies} with a single \texttt{PipelineLoadingScreen} component, and
\texttt{45dddf4} eliminated a redundant network round-trip by prefetching the completed
run detail inside \texttt{NewBacktest} and forwarding it via React Router state to
\texttt{RunResults}, so the results page renders immediately on navigation.

The AI Analyst modal received two related changes. \texttt{6056272} removed the private
\texttt{MetricsGrid} that had been duplicated inside the modal and replaced it with the
shared \texttt{MetricsPanel} component, rendered as a top strip with a new
\texttt{tourHook} prop to suppress the onboarding anchor when mounted inside a modal.
\texttt{fd57ede} switched the download action from a PDF (which required a synchronous
\texttt{jsPDF} render pass) to an interactive HTML report produced by
\texttt{exportReportHtml} (\texttt{38816c3}, PR~\#19). The HTML exporter inlines Plotly
and the newly added IBM Plex font bundle (WOFF2, self-hosted) so the exported file is
fully self-contained and viewable offline without a live server.

The second track was backtest isolation (\texttt{1acc780}). Previously
\texttt{GET /backtests} returned every run in the database, meaning two browsers would
see each other's history. The fix introduces an anonymous per-browser
\texttt{client\_id}: \texttt{frontend/src/api/clientId.ts} generates a UUID on first
load and persists it in \texttt{localStorage}; an Axios interceptor forwards it as
\texttt{X-Client-Id} on every request. The \texttt{BacktestRun} model gains a
nullable, indexed \texttt{client\_id} column; \texttt{POST /backtests} persists the
header value; \texttt{GET /backtests} filters to the caller's runs and returns an
empty list when the header is absent. A new integration test
(\texttt{tests/test\_backtest\_isolation.py}) asserts that two clients cannot see each
other's runs.

\subsection*{PDF export via headless Chromium (2026-06-01)}

Commit \texttt{b7996f6} (PR~\#21) replaced the earlier \texttt{jsPDF} single-pass
render with a server-side pipeline that produces print-quality A4 output. The
frontend assembles the full report document client-side using \texttt{exportReportHtml}
in a dedicated \texttt{"pdf"} mode --- the same utility that powers the interactive
HTML download --- and then \texttt{POST}s the self-contained HTML to the new
\texttt{POST /backtests/\{run\_id\}/report.pdf} endpoint. On the backend,
\texttt{backend/analytics/report\_pdf\_render.py} opens a headless Chromium instance
via Playwright's synchronous API, feeds it the HTML with \texttt{page.set\_content()},
waits for the embedded runtime to set \texttt{window.\_\_REPORT\_READY\_\_ = true}
(signalling that all Plotly figures have finished drawing), activates the report's
\texttt{@media print} CSS, and calls \texttt{page.pdf()} with A4 dimensions and
comfortable margins. The result is pixel-identical to the interactive report because
the same browser engine that displays it also renders it for the PDF.

Playwright is declared as an optional dependency in \texttt{requirements.txt} and its
\texttt{import} is deferred inside the route handler, so a missing Chromium installation
degrades only the \texttt{/report.pdf} endpoint and does not affect the rest of the
application. The production \texttt{Dockerfile} was updated to install the Playwright
Chromium bundle so the endpoint is available in the Railway deployment without any
manual setup step. A companion \texttt{PdfSectionsDialog} component lets the user
choose which sections to include in the rendered document before initiating the download.

\subsection*{Dockerfile base image pinned to bookworm (2026-06-01)}

Commit \texttt{b6718ce} (``Fix backend build: pin base image to
\texttt{python:3.11-slim-bookworm}'') addressed a build regression introduced by the
Chromium PDF feature shipped in PR~\#21. The floating \texttt{python:3.11-slim} tag
had quietly resolved to Debian trixie (13) on the Railway builder, where Playwright
1.49's \texttt{playwright install -{}-with-deps chromium} step fails because two font
packages have been renamed between Debian 12 and 13 (\texttt{ttf-unifont} and
\texttt{ttf-ubuntu-font-family}). Pinning the image to
\texttt{python:3.11-slim-bookworm} (Debian~12, which Playwright's own test matrix
covers) restored the build. A \texttt{\# Don't un-pin} comment was added in the
\texttt{Dockerfile} to record the reason for future contributors. This is a good
illustration of why production Dockerfiles should pin to an explicit OS image and not
rely on the ``latest minor'' behaviour of a floating tag.

\subsection*{Mobile-responsive navigation and UI (2026-06-01)}

Commit \texttt{b9414a7} (``Add responsive mobile nav and UI improvements'') introduced
mobile-first navigation to the frontend. The two principal additions are
\texttt{MobileNav}, a drawer + fixed top bar that collapses the \texttt{SideNav} on
narrow viewports, and \texttt{ScrollHint}, a thin wrapper that adds a scroll-affordance
cue to horizontally overflowing tables and the monthly returns heatmap.

Beyond navigation, the commit applied a systematic mobile-friendliness pass to nearly
every component on the results page: minimum touch-target sizes on interactive elements,
\texttt{touchAction: pan-y} on Plotly figures to prevent scroll capture, responsive grid
layouts in \texttt{MetricsPanel} and \texttt{TradeList}, and clamped font/dimension sizes
so the dense KPI grid remains legible on a phone without horizontal overflow. The
\texttt{viewport-fit=cover} meta tag was added to \texttt{index.html} to honour safe-area
insets on notched iOS/Android devices.

The design principle behind this change was \emph{additive responsiveness}: all
breakpoints are expressed via Tailwind's responsive prefix system, so the desktop layout
is unchanged and mobile improvements layer on top rather than forking a separate code
path.

\subsection*{Print path hardening (2026-06-03)}

Commit \texttt{1ebcae4} (``Add print sizing and \_\_printReport'') fixed a cluster of
print-quality defects in the self-contained HTML report produced by
\texttt{exportReportHtml}.

The root cause was a mismatch between how Plotly sizes charts on screen (responsive,
typically $\approx 900$~px wide) and the A4 print content column ($\approx 580$~px). When
the user triggered \texttt{window.print()}, Plotly's \texttt{ResizeObserver} did not refire
for the narrower print viewport, so charts overflowed and were clipped. Safari aggravated
the problem further: it fires the \texttt{beforeprint} event \emph{before} switching to
\texttt{@media print}, so a resize triggered there was still measured against the full
screen viewport rather than the page column. An unrelated Safari bug rendered the entire
print job blank when \texttt{.doc} carried \texttt{overflow: hidden}.

The fix introduces \texttt{window.\_\_printReport}: clicking ``Print / Save as PDF'' now
calls \texttt{Plotly.relayout} on every figure with explicit \texttt{width: 580} and
\texttt{height: 300} (360 for taller charts) before invoking \texttt{window.print()} with
a 250~ms settling delay, giving Plotly time to commit the resized SVGs before the browser
snapshot. Because the resize is \emph{explicit} rather than container-driven, it is
independent of when the browser switches media query. After the dialog closes,
\texttt{sizeForScreen} calls \texttt{Plotly.relayout} with \texttt{autosize: true} and
fires \texttt{Plots.resize} to restore the full-width interactive layout.
\texttt{beforeprint}/\texttt{afterprint} listeners apply the same sequence when the user
presses \keystroke{Cmd/Ctrl + P} directly.

CSS changes accompanied the runtime fix: \texttt{overflow: visible} was set on
\texttt{.doc} in \texttt{@media print}, the monthly-returns heatmap received
\texttt{width: 100\%; table-layout: fixed; font-size: 8.5px} so all 14 columns
(label + 12 months + Year) fit without clipping, and an \texttt{@page \{ size: A4;
margin: 12mm \}} rule pinned the paper format rather than relying on the user's browser
default.

\subsection*{Things we tried and abandoned}

A few decisions did not survive the four weeks:

\begin{itemize}
  \item \textbf{Asynchronous backtest submission.} The first design queued runs and
        polled status via WebSocket. We backed it out because synchronous \texttt{POST}
        worked well enough at v1 scale and removed an entire layer of state to debug.
        The Dashboard still polls \texttt{GET /backtests} every five seconds so it
        will surface any future async-submission feature without UI changes.
  \item \textbf{Postgres in development from day one.} We initially set up Docker
        Compose with Postgres but it slowed local iteration noticeably. SQLite became
        the default and the schema was kept on SQLAlchemy generic types so a
        \texttt{DATABASE\_URL} swap reaches Postgres without code changes.
  \item \textbf{LLM tool-use via the provider SDK's native function calling.} The
        Orchestrator Agent now parses tool calls from a JSON envelope in the model
        output rather than relying on Gemini's native function-calling API, because
        the latter is not directly portable to other providers. The cost is a
