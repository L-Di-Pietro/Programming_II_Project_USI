\section{Project diary}
\label{sec:diary}

The four-week development cycle was punctuated by eight merged pull requests and a
handful of direct-to-\texttt{main} commits for docs and trivia; a further 25 PRs
landed after submission, 15 of them opened automatically by the nightly
documentation agent. The narrative below follows the actual order of decisions,
with commit hashes given so a reviewer can verify any claim from \texttt{git log}.

\subsection*{Week~1 \textemdash{} Foundation (2026-04-25 to 2026-04-29)}

The first commit (\texttt{4ff85c1}) bootstrapped an empty repository. Four days
later, \texttt{ecdf3bb} (``Initial project scaffold for QuantEdge'') landed the
directory layout we would carry through the project: \texttt{backend/} with
\texttt{agents/}, \texttt{api/}, \texttt{analytics/}, \texttt{backtest/},
\texttt{data/}, \texttt{database/}, \texttt{llm/}, \texttt{strategies/}
subpackages, a \texttt{frontend/} folder primed for Vite, \texttt{tests/}, and a
pinned \texttt{requirements.txt}. The five agent boundaries (data, strategy,
backtest, analytics, explanation) were committed to at this stage
rather than discovered later, and held for the whole project.

\subsection*{Week~2 \textemdash{} First domain feature + first LLM call (2026-05-08)}

Two same-day commits were the project's two proofs of life. PR~\#1
(\texttt{376d30e}, ``feat: add TSLA as new equity asset'') validated the
end-to-end data path: seed an asset, run \texttt{load\_initial\_data.py}, see
daily bars in the database. \texttt{8997d20} (``feat: add LLM generated
report'') validated the LLM seam. We deliberately wrote the LLM feature
\emph{first} as a worst-case probe: if the \texttt{LLMProvider} abstraction could
carry a real response, every deterministic feature after it would be easier. It
worked, and the rest of the project never had to compromise its determinism for
the sake of the AI report.

\subsection*{Week~3 \textemdash{} Frontend MVP, hourly bars, charts (2026-05-12 to 2026-05-16)}

Frontend Version~1 (\texttt{1f2f5c7}) landed on 2026-05-12. The same day, PR~\#2
(\texttt{1f13139}, ``Add native calendars and hourly bar support'') reshaped the
data layer: the OHLCV primary key became \texttt{(asset\_id, ts, timeframe)} so
daily and hourly bars coexist, and the cleaner learned to reindex onto NYSE for
equities, 24$\times$5 for FX, and 24$\times$7 for crypto \textemdash{} the
project's most intricate single change, since a calendar edge case would silently
misstate every reported Sharpe ratio. A flurry of
chart fixes followed (\texttt{3e22d4c}, \texttt{162ceba}, \texttt{ab1e2de}),
\texttt{a3b6635} chunked bulk upserts past SQLite's parameter ceiling and added
LLM retries, and the first client-side PDF export shipped via \texttt{jsPDF}
(\texttt{0a7edb1}).

\subsection*{Week~4 \textemdash{} CI hardening, data layer, strategies, benchmarks (2026-05-19 to 2026-05-22)}

The week opened with two Claude Code GitHub Actions workflows:
\texttt{claude.yml} (\texttt{3d50b41}) for \texttt{@claude} mentions and
\texttt{claude-code-review.yml} (\texttt{6a38f60}) for an automatic review pass
on every PR \textemdash{} both respond only to explicit human triggers and never
self-merge. PR~\#4 (\texttt{4ce0311}, \texttt{820d610}) added the
\texttt{check-no-build-artifacts.yml} workflow after TypeScript compile outputs
leaked into \texttt{frontend/src/}. The data layer consolidated on yfinance as
primary source across all asset classes, with ccxt/Binance and Stooq fallbacks
(PR~\#5, \texttt{c2b6cce}); fixed-fractional sizing was corrected for crypto and
FX (PR~\#6, \texttt{ae082ef}). PR~\#7 (\texttt{b0676ed}) doubled the strategy
catalogue to ten (MACD, Ichimoku, Keltner, Time Series Momentum, Stochastic,
CCI), each registered, schema-exposed, and unit-tested on a known fixture.
PR~\#8 (\texttt{c0801c7}) added the
benchmark overlays: same-asset and SPY buy-and-hold curves computed and persisted
at run time, toggleable from a single shared chart legend. \texttt{d1efa3f}
(Quick-Start docs) and \texttt{4a9e6ae} (yfinance 0.2.46 $\to$ 1.3.0, which
pulled in \texttt{curl\_cffi}) closed the week.

\subsection*{Documentation pass (2026-05-24)}

\texttt{79e200a} refreshed the existing docs against the final code state, and a
second same-day pass created the artefacts the rubric requires, this PDF among
them: \texttt{AGENTS.md}, \texttt{CHANGELOG.md}, \texttt{CONTRIBUTING.md},
\texttt{CITATIONS.md}, \texttt{AI\_USAGE.md}, \texttt{SECURITY.md},
\texttt{CODE\_OF\_CONDUCT.md}, \texttt{docs/user-guide.md}, \texttt{docs/api.md},
\texttt{docs/architecture-diagrams/}, and the \texttt{docs/academic/} bundle.

\subsection*{Post-submission automation and hardening (2026-05-24 to 2026-06-07)}

On submission evening, PR~\#9 (\texttt{612e39e}) introduced
\texttt{nightly-docs.yml}: a GitHub Actions job that wakes at 02:00~UTC, runs
Claude Code headless with a read-only Bash allowlist, and opens a PR whenever it
finds documentation drift against the last 24~hours of commits \textemdash{} it
never touches \texttt{main} directly. \texttt{4dfc948} and PR~\#10
(\texttt{58a4811}) fixed its authentication and \texttt{id-token: write}
permission; PR~\#12 (\texttt{01d9c30}) bumped all workflows to the Node-24
action majors ahead of GitHub's runner retirement.

Substantive engineering continued alongside. PR~\#16 (\texttt{ed31a92},
\texttt{b8c9332}, \texttt{533dedb}) hardened \texttt{run.py}: TTY detection
before the API-key prompt, a fail-fast port check with a \texttt{kill} hint, and
tolerant \texttt{.env} parsing. \texttt{e1dd918} added a production frontend
Dockerfile and Postgres URL normalisation for Railway deployment. On 2026-05-29
a frontend polish sprint (\texttt{b3acd7d}, PR~\#18, \texttt{45dddf4},
\texttt{6056272}) shipped the interactive onboarding tour, a unified loading
screen, and run-detail prefetching, while PR~\#19 (\texttt{38816c3},
\texttt{fd57ede}) made the downloadable report a self-contained interactive HTML
file. The same day, \texttt{1acc780} introduced per-browser backtest isolation:
an anonymous \texttt{client\_id} minted in \texttt{localStorage} and forwarded as
\texttt{X-Client-Id} scopes \texttt{GET /backtests} to the caller, with an
integration test asserting two clients cannot see each other's runs.

PR~\#21 (\texttt{b7996f6}, 2026-06-01) replaced the \texttt{jsPDF} export with a
print-quality pipeline: the frontend assembles the self-contained report HTML and
\texttt{POST}s it to \texttt{/backtests/\{run\_id\}/report.pdf}, where headless
Chromium (Playwright) renders A4 output identical to the interactive report.
\texttt{b6718ce} pinned the backend image to \texttt{python:3.11-slim-bookworm}
after a floating tag silently resolved to Debian~13 and broke Chromium's font
dependencies. \texttt{b9414a7} added mobile-first navigation, and
\texttt{1ebcae4} (2026-06-03) fixed print sizing by relaying out every Plotly
figure to the A4 column width before \texttt{window.print()}. \texttt{855c0a6}
(2026-06-05) repaired the missing \texttt{\textbackslash keystroke} macro this
document uses and completed the author list. Finally, PR~\#30 (2026-06-07) added
the \texttt{MobileDesktopBanner} and suppressed the onboarding tour below the
desktop breakpoint (\texttt{7ca67e8}), rebranded the project from QuantBacktest
to QuantEdge across every file (\texttt{da11eaf}), and moved the port check to
the second step of \texttt{run.py} so conflicts abort in under a second
(\texttt{a0b8ac2}).

\subsection*{Steady state and final pass (2026-05-25 to 2026-06-11)}

From 2026-05-25 onward the nightly workflow fired every night, producing 15
merged PRs through \#33. On nights following human commits it recorded them in
\texttt{CHANGELOG.md}, this diary, and the user guide; on quiet nights it
recorded only the previous nightly commit itself. No nightly run ever modified
code, confirming that the documentation-only write scope and read-only Bash
allowlist behave as designed. A final pre-submission pass on 2026-06-11 populated
Table~\ref{tab:results} from a backtest executed against the final codebase,
captured the user-guide screenshots from a live local instance, compressed this
diary \textemdash{} which nightly appends had grown well past the rubric's page
budget \textemdash{} and recompiled this PDF.

\subsection*{Things we tried and abandoned}

A few decisions did not survive the four weeks:

\begin{itemize}
  \item \textbf{Asynchronous backtest submission.} The first design queued runs and
        polled status via WebSocket. We backed it out because synchronous \texttt{POST}
        worked well enough at v1 scale and removed an entire layer of state to debug.
  \item \textbf{Postgres in development from day one.} We initially set up Docker
        Compose with Postgres but it slowed local iteration noticeably. SQLite became
        the default and the schema was kept on SQLAlchemy generic types so a
        \texttt{DATABASE\_URL} swap reaches Postgres without code changes.
\end{itemize}
